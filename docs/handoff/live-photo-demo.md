# «Живое фото» к показу

Передача ведущему показ. Состояние на 25.09.2026, `main` на коммите `e526e43`.

**Если что-то пошло не так:**

- «Включаем камеру…» не проходит или ошибка камеры → «Смотреть без камеры», дальше по плану C. На версии без #11 кнопки в этот момент может не быть: закройте экран крестиком и нажмите «Смотреть без камеры» на странице.
- Нет звука на iPhone → выключить беззвучный режим. Звук включается только после нажатия кнопки на странице.
- Снимок не узнаётся → весь снимок в кадре, без бликов, печать не меньше A5.

## Ограничения камеры

- **Только HTTPS или localhost.** На `http://marshrutypobedy.ru` браузер не даёт камеру. После #11 страница пишет «Камера работает только на защищённом адресе (https://)» и предлагает ролик. Нужно: Settings → Pages → Enforce HTTPS, когда GitHub выпустит сертификат.
- **Сеть при первом включении камеры.** three.js и MindAR (около 1,7 МБ) грузятся с jsDelivr в момент нажатия. Новый service worker (только на HTTPS) сохраняет их и цели `.mind` после первого раза. Ролики и субтитры он не сохраняет — без сети ролик не сыграет, если браузер не держит его в своём кэше. Без сети после #11 — ошибка не позже чем через 20 с и переход к ролику.
- **Узнаётся только свой снимок**: на странице офицера — только офицер. Снимок целиком в кадре, без бликов.
- **Звук** включается только после нажатия кнопки на странице. На iPhone беззвучный режим глушит ролик.
- **Без #11 на сайте**: при сбое загрузки цели экран висит на «Включаем камеру…» с горящей камерой; при свёрнутом браузере камера не гаснет; в режиме камеры нет субтитров; тексты обещают создать ролик по своему фото.
- **Генерации нет.** «Оживить своё фото» только сохраняет снимок на телефоне; ролик по нему не создаётся.

## APK

Не собран. Решение: до защиты не делаем. На машине команды есть Node 24 и Java 8 без компилятора; нет JDK 17+, Android SDK (API 36), Android Studio. Capacitor в проект не подключён, папки `android/` нет — веб-версия не затронута.

Проверить готовность среды: `node scripts/android-env-check.mjs` в `frontend/` (после слияния #13). Отчёт и план на после защиты — PR [#13](https://github.com/team-shpilit/lexa-lepexa/pull/13).
