# Связка фронтенда и бэкенда

Ветка `integration/fullstack`: фронт из `frontend` и бэк из `backend-no-postgis`, соединённые и проверенные вместе.
Аудит, с которого всё началось: 30 запросов фронта, из них 5 работали, 5 отвергались из-за формата, 19 отвечали 404,
поток уведомлений не доставлял событий.

## Что было сломано и что сделано

| Было | Стало |
| ---- | ----- |
| На сервере 11 эндпоинтов из нужных фронту | Все 27 эндпоинтов контракта и поток уведомлений; сверка — 28 из 28 |
| Даты `…+00:00`, а фронт принимал только `…Z` | Сервер отдаёт `…Z`; фронт принимает оба варианта (`z.iso.datetime({ offset: true })`) |
| `"url": null` у источника без ссылки | Пустые поля не сохраняются и не отдаются |
| SSE слал буквальные `\n\n` — браузер не видел событий | Настоящие переводы строки, `id:` у события, продолжение после обрыва по `Last-Event-ID`, пинг каждые 15 с |
| Поток при подключении присылал все старые уведомления | Только новые |
| Фронт не передавал, кто пользователь | Ключ вкладки в `X-Demo-User`, в потоке — `?user=`; автор не получает уведомление о своей находке |
| CORS с опечаткой в коде | Только из переменной `CORS_ORIGINS` |
| База на сервере пустая | Демо-данные фронта заливаются при старте (`app/seed.py`), без дублей |
| `backend/Dockerfile` не копировал `start.py` | Исправлено; есть общий `docker-compose.yml` |
| Расхождения никто не ловил | CI: миграции на Postgres + сверка всех эндпоинтов со схемами фронта |

## Решения

- **Ветка без PostGIS.** Радиус 20 км по сотне подписок считается в Python мгновенно, а обычный Postgres есть
  у любого хостинга, включая текущий Deploy-F. Ветку `backend` с PostGIS можно закрыть; если позже понадобятся
  тяжёлые геозапросы, PostGIS добавляется отдельной миграцией.
- **Контракт — во фронте.** `frontend/src/contract` остаётся единственным источником правды; `docs/openapi.json`
  генерируется из него. Бэкенд повторяет поля и ограничения в `app/schemas.py`, а CI проверяет, что ответы проходят схемы фронта.
- **Отдельные таблицы под контракт.** Новые таблицы (`trail_routes`, `volunteer_requests`, `fundraisers`, `trips`,
  `group_applications`, `archive_stories` и др.) не пересекаются с целевой схемой 0002 (`routes`, `donations`, …) —
  тот же подход, что у таблиц 0001. Вложенные структуры, которые фронт всегда получает целиком (линия маршрута,
  задание на точке, чек-лист), лежат в JSON-колонках.
- **Демо-данные из одного места.** `npm run seed:backend` выгружает фикстуры фронта в `backend/app/seed_data.json`,
  поэтому сайт на настоящей базе выглядит так же, как демо. CI падает, если файл устарел.
- **Демо-пользователь вместо входа.** Как и в моках: списки отдаются целиком, экран фильтрует по роли.
  С появлением входа фильтры переедут на сервер, контракт не изменится.

## Где запускать

**Сейчас (без затрат).** Фронт — GitHub Pages, бэк — Deploy-F (`https://a49734-6295.q.d-f.pw`).
После слияния нужно обновить бэк на Deploy-F до этой версии — см. [`backend/DEPLOY-F.md`](../backend/DEPLOY-F.md).
Адрес API для сборки Pages — переменная репозитория `API_URL` (по умолчанию — текущий Deploy-F).

**Для постоянной работы.** VPS в РФ и `docker compose up -d --build` в корне: Postgres, API и фронт за Caddy
на одном домене, HTTPS выпускается автоматически, CORS не нужен. Для этого в `.env` задаются `SITE_ADDRESS=домен`,
`HTTP_PORT=80`, `HTTPS_PORT=443` и пароль базы.
