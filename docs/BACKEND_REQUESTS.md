# Что фронтенду нужно от бэкенда

Файл ведёт фронтенд. Бэкендер отмечает статус в квадратных скобках: `[ ]` не начато, `[~]` в работе, `[x]` готово, `[-]` не будем (с причиной).

## Инфраструктура
- [ ] **HTTPS.** Фронт работает только по HTTPS (геопозиция, service worker, уведомления). Страница по HTTPS не может ходить к API по HTTP (mixed content).
- [ ] **Тот же домен через прокси `/api`** — предпочтительно: тогда CORS не нужен. Готовый пример — `frontend/deploy/Caddyfile` (`reverse_proxy` на порт бэкенда).
- [ ] Если API на отдельном домене — **CORS** для домена фронта: `GET, POST, PATCH, OPTIONS`, заголовок `Content-Type`.
- [ ] Базовый путь `/api/v1`.

## Контракт
- [ ] Посмотреть и подтвердить `docs/API_CONTRACT.md` / `docs/openapi.json` или предложить правки (camelCase, форматы дат, статусы).
- [ ] Если будет свой OpenAPI (например, FastAPI) — отдавать его по `/api/v1/openapi.json`, фронт будет генерировать из него типы.
- [ ] Ошибки в формате `{ "message": string }`.

## Данные
- [ ] Загрузить данные жюри (`mock_graves.csv`, `mock_battles.json`, `mock_teams.json`). Пока их нет, фронт использует демо-файлы той же схемы из `frontend/fixtures/jury/`, они подходят и для сидов.
- [ ] Поле `demo` у синтетических и непроверенных записей.

## Функциональность P0
- [ ] `POST /sites` с рассылкой подписчикам в радиусе 20 км и `notifiedCount` в ответе (см. раздел «Ключевой сценарий» в контракте).
- [ ] Поток уведомлений `GET /notifications/stream` (SSE). Web Push с VAPID — позже.
- [ ] Вход без регистрации для демо: как сервер различает роли (демо-токен или заголовок роли)? Предложите вариант.
