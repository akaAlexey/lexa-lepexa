## 3. Находки подробно

### SEC-01 — Нет авторизации: роли существуют только на клиенте

- **Severity:** Critical. **Класс:** уязвимость. **Область:** API, роли, «Живая память», «Последний бой».
- **Где:**
  - `backend/app/identity.py:14-25`: личность — это произвольная строка из `X-Demo-User`/`?user=`, по умолчанию `"demo"`.
  - Ни один роутер не проверяет роль:
    - `backend/app/routers/sites.py:43-119`: создание места, смена статуса, «готов помочь»;
    - `sites.py:143-148`: удаление любой подписки по id;
    - `backend/app/routers/stories.py:51-64`: решение по истории, `reviewer` берётся из тела запроса;
    - `backend/app/routers/trips.py:71-77`: решение по коллективной заявке;
    - `backend/app/routers/search_hq.py:22-38`: заявка от имени любого отряда.
  - Роль выбирается одним нажатием и хранится в localStorage (`frontend/src/app/RoleContext.tsx:16-24`). Права
    проверяются только в UI (`frontend/src/functions/core/permissions.ts:26-40`).
- **Воспроизведение** (API без заголовков, проверено):
  ```bash
  B=http://127.0.0.1:8000/api/v1
  # «Подтверждено архивом» без роли краеведа → 200
  curl -X PATCH $B/sites/<id>/status -H 'Content-Type: application/json' \
    -d '{"status":"archive_confirmed","source":{"kind":"archive","title":"fake"}}'
  # Значок «Подтверждено» у любой истории от имени «Главный краевед» → status=verified
  curl -X POST $B/stories/<id>/review -H 'Content-Type: application/json' \
    -d '{"decision":"verified","reviewer":"Главный краевед","note":""}'
  # Подтвердить чужую коллективную заявку → confirmed
  curl -X PATCH $B/group-applications/G01 -H 'Content-Type: application/json' -d '{"status":"confirmed"}'
  # Удалить чужую подписку → {"ok":true}
  curl -X DELETE $B/subscriptions/SUB-DEMO-1
  # Заявка от имени отряда T02 на 999 999 человек → 200
  ```
- **Ожидается:** менять статусы мест, проверять истории и решать по заявкам может только пользователь с
  подтверждённой ролью. Удалить подписку может только её владелец.
- **Фактически:** всё это доступно анонимно.
- **Влияние:** главная ценность продукта — проверка краеведом («значок “Подтверждено”», задача 6 кейса) и статусы
  «Подтверждено архивом»/«Останки подняты» (задача 8) — ничего не гарантирует. Публичное демо на Pages ходит в
  общую живую базу (CI-02), поэтому любой посетитель может испортить данные, которые увидит жюри.
- **Минимальное исправление:** выдавать демо-роль с сервера подписанным токеном (JWT/HMAC со сроком жизни). Пока
  входа нет — хотя бы для командира и краеведа по демо-коду. Добавить зависимость
  `require_role("verifier"|"commander")` на изменяющие эндпоинты. Для подписок хранить владельца и сверять его при
  `DELETE`. `reviewer` брать из токена, а не из тела.
- **Регрессионные тесты:** `pytest` без токена и с токеном роли `family` — 401/403 на `PATCH /sites/{id}/status`,
  `POST /stories/{id}/review`, `PATCH /group-applications/{id}`, `POST /requests`, `POST /sites`; `DELETE
  /subscriptions/{id}` чужим ключом — 403/404; с правильной ролью — 200.

### SEC-02 — Точные координаты мест гибели доступны всем

- **Severity:** Critical. **Класс:** уязвимость и несоответствие заявленной этике. **Область:** API, карта «Последний бой».
- **Где:**
  - `backend/app/serializers.py:155-160`: `site()` всегда отдаёт `lat`/`lon` как есть;
  - `backend/app/routers/sites.py:33-40`: `GET /sites` и `GET /sites/{id}` без проверки роли;
  - `frontend/src/features/last-battle/LastBattleScreen.tsx:40-47`: метка-«зона» строится по точным `site.lat/lon`;
  - `frontend/src/features/last-battle/SiteScreen.tsx:82-84, 147-155`: координаты скрываются только в текстовой
    карточке. Комментарий в коде сам признаёт: «настоящее скрытие должен делать сервер»;
  - `README.md:94` утверждает обратное: «Точные координаты … видят только командиры отрядов и краеведы, остальные —
    район около 500 м».
- **Воспроизведение** (проверено):
  ```bash
  curl -X POST $B/sites -H 'Content-Type: application/json' -d '{"lat":52.965123,"lon":36.078456,
    "placeName":"Audit","fightersCount":1,"fighters":[{}],"unit":"x","dateText":"1941",
    "sources":[{"kind":"archive","title":"t"}]}'
  curl $B/sites/<id>        # → "lat":52.965123,"lon":36.078456 — анонимно, до 6 знаков
  ```
  В браузере: роль «Семья» → «Последний бой». Центр пунктирной зоны на карте совпадает с точной точкой, а ответ
  `GET /sites` виден во вкладке Network.
- **Ожидается:** не-поисковику сервер отдаёт координаты, огрублённые до района около 500 м со случайным смещением,
  которое стабильно для каждого места.
- **Фактически:** точные координаты получает любой. У демо-мест они огрублены до 0,01° только потому, что так
  записаны в seed.
- **Влияние:** прямо противоречит заявленной защите от «чёрных копателей» — этическому требованию, на котором
  стоит модуль «Последний бой». Реальный командир, опубликовав находку, раскроет место захоронения всем.
- **Минимальное исправление:** в `serializers.site()` принимать роль из токена (SEC-01). Для посторонних отдавать
  координаты, огрублённые до сетки около 500 м со смещением от `hash(site.id)`, и флаг `coordsApproximate: true`.
  Центр зоны на карте брать из этих данных. В `notifications` и других ответах точные координаты тоже не отдавать.
- **Регрессионные тесты:** `pytest`: `GET /sites` и `GET /sites/{id}` без роли — расстояние до точной точки
  больше 100 м и не больше 700 м, повторный запрос даёт то же значение; с ролью `commander`/`verifier` — точные
  координаты. e2e: роль «Семья» — в ответе `/sites` нет точных координат из фикстуры.

### TD-01 — Незакреплённые зависимости: чистая установка бэкенда уже падает

- **Severity:** High. **Класс:** техдолг, ведущий к функциональному отказу. **Область:** зависимости, Docker, CI, Deploy-F.

- **Воспроизведение** (проверено):

- **Фактически:** следующий запуск CI без кэша, `docker compose build` или переустановка на Deploy-F поставят 2.1

### FUN-01 — Потерянные обновления счётчиков (гонка read-modify-write)

- **Severity:** High. **Класс:** функциональный дефект (целостность данных, в том числе денег). **Область:** API, БД.
- **Где:** `backend/app/routers/search_hq.py:44` (`x.joined += 1`), `search_hq.py:59` (`f.collected_rub +=
  body.amount_rub`), `backend/app/routers/sites.py:116` (`site.volunteers_ready += 1`): чтение без блокировки,
  запись значения, вычисленного в Python.
- **Воспроизведение** (Postgres 16, проверено):
  ```bash
  for i in $(seq 20); do curl -s -o /dev/null -X POST $B/requests/R01/join & done; wait
  # joined: 2 → 4, при этом строк в volunteer_request_joins добавилось 20
  for i in $(seq 20); do curl -s -o /dev/null -H 'Content-Type: application/json' -X POST $B/donations \
    -d '{"fundraiserId":"F02","amountRub":1}' & done; wait
  # collectedRub: 9000 → 9004 вместо 9020
  ```
- **Ожидается:** `joined` и `collectedRub` равны сумме записанных строк.
- **Фактически:** 18 из 20 записей и 16 ₽ из 20 ₽ потеряны.
- **Влияние:** счётчик собранных денег расходится с журналом платежей. С реальной ЮKassa это уже
  финансовое расхождение.
- **Минимальное исправление:** атомарный `UPDATE … SET joined = joined + 1 RETURNING …` (SQLAlchemy:
  `update(...).values(joined=Model.joined + 1)`) или `with_for_update=True`, как уже сделано в `trips.py:29`.
  Лучше считать сумму из `fundraiser_donations`.

- **Влияние:** участники отряда-автора, подписанные с других устройств, получают уведомление о собственной находке.
- **Исправление:** брать отряд из токена роли (SEC-01) или слать заголовок из фронта.

### FUN-07 — «Найдено бойцов за месяц» — статичное число

- **Severity:** Low. **Класс:** несоответствие кейсу / целостность данных. **Где:** `backend/app/routers/jury.py:28-31`
  суммирует поле `teams.found_this_month` из seed и подписывает его текущим месяцем (`now().strftime("%Y-%m")`).
- **Влияние:** счётчик на главном экране «Поисковикам» не меняется при переводе мест в «Останки подняты» и через
  месяц покажет прошлые данные как текущие.
- **Исправление:** считать по `last_battle_sites` со статусом `remains_raised` за текущий месяц или подписывать
  источник и дату данных.
- **Регрессионный тест:** перевод места в `remains_raised` → `foundThisMonth` вырос на `fightersCount`.

### FUN-08 — Неизвестный статус места даёт 500

- **Severity:** Low. **Класс:** функциональный дефект. **Где:** `backend/app/routers/sites.py:103`:
  `STATUS_ORDER.index(site.status)` бросает `ValueError`, если в БД статус вне списка. Колонка `status` в
  `last_battle_sites` nullable (TD-02), ограничения `CHECK` нет.
- **Исправление:** `CHECK (status IN (...))` в миграции; в коде `if site.status not in STATUS_ORDER: fail(409, …)`.
- **Регрессионный тест:** место со статусом `NULL`/`"x"` → `PATCH …/status` возвращает 409, а не 500.

### SEC-07 — Hardening: заголовки, документация API, доверие прокси

- **Severity:** Low. **Класс:** уязвимость (hardening). **Где:** `frontend/deploy/Caddyfile.docker:4-25` и
  `frontend/deploy/Caddyfile`: нет `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`,
  `frame-ancestors`/`X-Frame-Options`, `Permissions-Policy` (сайт просит геопозицию и камеру).
  `backend/app/main.py:9-14`: `/api/v1/docs` и `/api/v1/openapi.json` открыты в проде.
  `backend/start.py:38-40`: `--proxy-headers --forwarded-allow-ips *` доверяет `X-Forwarded-For` от любого клиента.
  Сейчас IP нигде не используется, но будущий rate limit (SEC-06) будет обходиться.
- **Исправление:** блок `header { … }` в Caddy; `docs_url=None` по флагу окружения; `--forwarded-allow-ips` —
  адрес прокси.
- **Регрессионный тест:** `curl -I localhost:8080/` содержит `content-security-policy` и `x-content-type-options:
  nosniff`.

### SEC-08 — Контракт фронта принимает `javascript:`/`data:` URL

- **Severity:** Low. **Класс:** defense in depth. **Где:** `frontend/src/contract/schemas.ts:49, 73, 83, 229`: `z.url()`.
- **Воспроизведение:** `node -e "const {z}=require('zod');console.log(z.url().safeParse('javascript:alert(1)').success)"` → `true`.
  Ссылки рендерятся в `href` (`frontend/src/ui/SourceList.tsx:13`, `ChronicleScreen.tsx:193` и др.).
- **Смягчающие факторы:** бэкенд ограничивает пользовательские источники `^https?://` (`schemas.py:26`), а
  React 19 блокирует `javascript:` в `href`. Эксплуатация не подтверждена.
- **Исправление:** `z.url({ protocol: /^https?$/ })`.
- **Регрессионный тест:** unit-тест контракта: `javascript:`/`data:` отклоняются.

### SEC-09 — Конфигурация Docker

- **Severity:** Low. **Класс:** уязвимость (конфигурация). **Где:**
  - `docker-compose.yml:14, 26`: `${POSTGRES_PASSWORD:-postgres}` — без `.env` поднимается с паролем `postgres`;
  - `backend/docker-compose.yml:9`: `5432:5432` на всех интерфейсах с `postgres/postgres`, если dev-compose запустить
    на сервере;
  - `backend/Dockerfile`: нет `USER`, процесс работает от root.
- **Исправление:** `${POSTGRES_PASSWORD:?задайте POSTGRES_PASSWORD}`, `127.0.0.1:5432:5432`, непривилегированный
  пользователь в образе.
- **Регрессионный тест:** `docker compose config` без `.env` падает с понятной ошибкой;
  `docker compose exec api id -u` не равно 0.

### UX-01 — Тяжёлый бандл для целевой аудитории

- **Severity:** Low. **Класс:** UX / производительность. **Где:** сборка `vite build`: `index-*.js` 625 КБ,
