# «Живое фото» и мобильная упаковка: границы работ

Аудит от 25.09.2026 по `main` на коммите `56a21ca`. Код в этом шаге не менялся.

## Итог

- **P0 (QR → оговорка → согласие → видео и субтитры)** в коде готов и покрыт тестами. Но цепочка рвётся на первом шаге: **QR на обоих снимках ведёт на адрес, который отдаёт 404**. Пока снимки не перепечатаны с новым QR, показ по бумажному снимку не работает.
- **P1 (AR с камерой)** распознаёт оба снимка и запускает ролик поверх. «Закрыть» корректно выключает камеру. Есть 3 дефекта: зависание с включённой камерой при сбое загрузки цели, камера не гаснет на скрытой вкладке, в режиме AR нет субтитров. И блокер окружения: **новый домен работает только по HTTP**, а без HTTPS браузер не даёт камеру.
- **P2 (APK через Capacitor)**: окружение не готово. Capacitor не подключён, Android SDK нет, Java 8 вместо 21. В этом шаге P2 не делаем.
- **Генерации ролика по своему снимку в продукте нет.** Оба ролика собраны заранее вручную во внешних сервисах. Экран «Оживить своё фото» только сохраняет снимок на устройстве, но интерфейс в трёх местах обещает генерацию. Эти тексты нужно исправить в P0.

## P0 — QR → этическая оговорка → согласие → видео и субтитры

**Результат.** Человек сканирует QR на распечатанном снимке, попадает на `/live/<id>` нужного снимка, видит оговорку, ставит согласие и смотрит ролик со звуком, русскими субтитрами и плашкой «Реконструкция с помощью ИИ». Камера для P0 не нужна. Про генерацию по своему снимку интерфейс нигде не обещает.

**Работы:**

1. **LP-1.** Выбрать постоянный адрес QR. Рекомендация: `https://marshrutypobedy.ru/live/<id>` (после LP-5) или `https://team-shpilit.github.io/lexa-lepexa/live/<id>` — он уже редиректит на домен. Поменять `BASE` в `stamp_qr.py`, заново наложить QR на исходные снимки. QR — часть распознаваемого изображения, поэтому **после перештамповки перекомпилировать `.mind`** (`node scripts/live-photo/compile_targets.mjs public/live soldier reichstag`), обновить адреса в `docs/LIVE_PHOTO.md` и перепечатать снимки.
2. **LP-2.** Переписать три текста без обещаний, например: «В демо ролик по вашему снимку не создаётся: снимок сохраняется только на этом устройстве. Ниже — пример ролика, собранного командой вручную по другому снимку». Обновить тест `NewLivePhoto.test.tsx`.
3. **LP-3.** В шаге сборки Pages копировать `index.html` в `dist/live/<id>/index.html` для каждого снимка: тогда адрес из QR отвечает 200.
4. **LP-4.** Указать для каждого снимка автора, архив и лицензию в `sources`. Если атрибуции нет, снимок на публичный показ не печатать.

**Приёмка:**

- QR с напечатанных `soldier` и `reichstag` открывает свою страницу на телефоне, HTTP 200.
- До согласия обе кнопки неактивны; оговорка видна без прокрутки на 360 px.
- «Смотреть без камеры»: ролик со звуком, субтитры включены по умолчанию, плашка ИИ видна; работает по HTTP и HTTPS.
- В интерфейсе нет слов «оживит», «соберёт сервер», «следующий этап» применительно к своему снимку.
- Зелёные: `LivePhoto.test.tsx`, `NewLivePhoto.test.tsx`, `e2e/live-photo.spec.ts` в двух размерах экрана, axe AA.

## P1 — AR с камерой: корректная остановка, fallback и видимая пометка ИИ

**Результат.** На телефоне по HTTPS «Навести камеру» включает AR: снимок узнаётся, ролик играет поверх, плашка ИИ и субтитры видны. Камера гаснет при закрытии, ошибке, таймауте, скрытии вкладки и уходе со страницы. Любой сбой за разумное время ведёт в «Смотреть без камеры».

**Работы:**

1. **LP-5.** Дождаться сертификата GitHub для `marshrutypobedy.ru` и включить **Enforce HTTPS** (Settings → Pages). До этого показ AR — только с `https://team-shpilit.github.io/...`, если на нём нет редиректа на HTTP. Сейчас редирект есть.
2. **LP-6.** В `trackImage`: `try/catch` вокруг `mindar.start()` с `mindar.stop()` и освобождением текстуры и геометрии при ошибке; в `ArView` — таймаут запуска (например, 20 с), после которого сессия останавливается и показывается fallback.
3. **LP-7.** В `ArView`: на `visibilitychange` (hidden) и `pagehide` останавливать сессию и ставить ролик на паузу. При возврате — предложить «Включить камеру снова», а не включать молча.
4. **LP-8.** Дорожка `.vtt` в режиме `hidden`; текущая реплика (`cuechange`) выводится в нижней панели AR рядом со статусом.
5. **LP-9.** Положить three 0.160.0 и MindAR 1.2.5 в сборку (npm-зависимости или `public/vendor/`) вместо jsDelivr. `importmap` направить на свои файлы. Версии не менять.
6. **LP-10.** Положить в репозиторий генератор `.y4m` из снимка (сейчас поток делался вручную); добавить в AR-тест проверки «камера `ended` после закрытия», «после сбоя `.mind` — fallback за N с и камера `ended`», «скрытая вкладка → `ended`»; запускать AR-тест в отдельной задаче CI с сетью.

**Приёмка:**

- Виртуальная камера, оба снимка: «Снимок ожил», ролик играет, плашка ИИ и текущая реплика видны.
- После «Закрыть», сбоя `.mind` (404), таймаута и скрытия вкладки все дорожки `getUserMedia` в состоянии `ended`, ролик на паузе.
- При отказе в доступе к камере и на `http://` — понятная ошибка и «Смотреть без камеры», без зависания.
- Ручная проверка на одном Android (Chrome) и одном iPhone (Safari): распознавание, звук после нажатия, закрытие гасит индикатор камеры.

## P2 — APK через Capacitor (только если окружение готово)

**Решение:** в этом шаге не делаем. Окружение не готово (LP-11), а ставить его — отдельная работа, не часть AR.

**Что нужно, чтобы начать:**

- JDK 21, Android SDK (platform-tools, build-tools, платформа API 35), `ANDROID_HOME`; Android Studio или `sdkmanager` + Gradle wrapper.
- `@capacitor/core`, `@capacitor/cli`, `@capacitor/android` одной мажорной версии; `capacitor.config.ts` (`webDir: dist`), `npx cap add android`.
- Разрешение `CAMERA` в `AndroidManifest.xml`. AR остаётся веб-AR (MindAR) внутри WebView: Capacitor передаёт WebView запрос камеры после системного разрешения. Нативного AR нет и в этом объёме не будет — ADR 0011 нужно поправить.
- Для офлайна в APK — сначала LP-9 (без CDN), иначе AR в приложении зависит от сети.
- Подпись: debug-ключ для показа; ключ выпуска и RuStore — отдельная задача.

**Приёмка, когда до P2 дойдёт очередь:** `npx cap sync android && ./gradlew assembleDebug` собирает APK; на телефоне без сети после установки открываются `/live/soldier`, ролик с субтитрами и AR по распечатанному снимку; закрытие гасит камеру.

## Что не обещаем

- Генерацию ролика по загруженному снимку — ни в приложении, ни на сервере. Для новых снимков это ручной процесс команды (`docs/LIVE_PHOTO.md`: голос ElevenLabs, лицо Hedra или Kling) с согласием родственников.
- Озвучку фразы из кейса «Я сделал это, чтобы ты жил и видел голубое небо. Помни меня.»: она есть только текстом на `/live/new`, в готовых роликах звучат другие реплики.
- Нативный AR в Android.
