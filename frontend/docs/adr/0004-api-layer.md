# ADR 0004. API-слой: zod-контракт, OpenAPI, адаптеры mock и live

- Статус: принято
- Контекст: бэкенд пишет другой участник, его ещё нет. Фронт не должен его ждать, а контракт не должен разойтись.

## Решение
- **Источник правды — zod-схемы** в `src/contract/schemas.ts` и таблица эндпоинтов `src/contract/endpoints.ts`.
- **OpenAPI 3.0 генерируется** из них: `npm run contract` пишет `docs/openapi.json`. Тест падает, если файл отстал от кода. Бэкендер берёт этот файл; если у бэкенда появится свой OpenAPI — разворачиваем направление и генерируем схемы из него.
- **Один интерфейс `ApiClient`** выводится из таблицы эндпоинтов (типы параметров пути и тела — на уровне TypeScript). Его реализуют:
  - `mock` — in-memory «сервер» на фикстурах: задержка (`VITE_MOCK_LATENCY_MS`), доля ошибок, проверка тел запросов теми же схемами, радиус 20 км, BroadcastChannel между вкладками для показа «командир → волонтёр» без бэкенда;
  - `live` — `fetch` к `VITE_API_URL`; каждый ответ проверяется схемой, расхождение — `ContractError` (в dev громко в консоль). Уведомления — SSE `/notifications/stream`.
- **Переключение** — `VITE_API_MODE=mock|live`. Конфигурация проверяется zod при старте: `live` без URL не запустится.
- **Фикстуры** в формате жюри (`fixtures/jury`) конвертирует скрипт `npm run fixtures` с проверкой схемой (CSV не парсится в рантайме).

## Последствия
- Экраны не знают, откуда данные; тесты подменяют API целиком.
- Имена полей — camelCase, даты — ISO 8601. Об этом договариваемся с бэкендером в `docs/BACKEND_REQUESTS.md`.
