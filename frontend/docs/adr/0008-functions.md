# ADR 0008. Функции отдельно от страниц

- Статус: принято (итерация «релизная раскладка», 2026-09-24, после ревью staff-инженера)
- Контекст: сценарии живут в экранах. 18 файлов `features/` сами ходят в API, платформу и кэш. Память на устройстве устроена по-разному в 9 местах, проверки ролей повторяются в 8 местах, 4 формы повторяют одну механику. Раскладка меняется на референс «Полевой атлас», дальше будет Android, а команда хочет включать и выключать функции без переписывания экранов. Бэкенд подстраивается под фронт, поэтому ему нужно видеть, какая функция каким эндпоинтом пользуется.

## Решение

**Функция** — это папка `src/functions/<функция>/` без JSX. В ней сценарий, его правила и работа с API, кэшем, платформой и памятью на устройстве:

- `<сценарий>.ts` — чистая функция `(deps, input) → Promise<Result>`, где `deps = { api, platform, now, own }`. Без React, DOM и роутера. Её же вызовет Android-оболочка или другой стек.
- `use<Сценарий>.ts` — тонкий хук: TanStack Query или Mutation, инвалидация кэша. Навигацию делает экран, хук только возвращает результат.
- `*.test.ts` — тесты сценариев на mock-API: успех, ошибка проверки, ошибка сети.
- `index.ts` — публичный API функции. Снаружи импортируют только его.

**Экран** (`features/*`, после шага B — `screens/*`) только собирает раскладку из `ui/`, `map/` и хуков функций.

**Общие механизмы** — `src/functions/core/`. Функции пользуются ими, а core не зависит ни от одной функции:

| Механизм             | Файл                                    | Что заменяет                                                                                                                                                               |
| -------------------- | --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Зависимости          | `deps.ts`, `useDeps.ts`                 | Прямые вызовы `useServices()` в экранах. `useDeps` — единственный хук, который берёт сервисы                                                                               |
| Память на устройстве | `deviceMemory.ts`, `useDeviceMemory.ts` | 9 разрозненных ключей и `useState + storage.get/set`. Ключи прежние: данные на телефонах не теряются                                                                       |
| Модель формы         | `form.ts`, `useForm.ts`                 | 4 формы по 8–9 `useState` с одинаковой проверкой и фокусом на первой ошибке                                                                                                |
| Ключи кэша           | `queryKeys.ts`                          | Ключи-строки в 12 местах                                                                                                                                                   |
| Адреса экранов       | `paths.ts`                              | `pointUrl`, `storyUrl`, `` `/last-battle/${id}` `` и т. п. Это единственное место, где записаны URL. На шаге B здесь меняются адреса, а старые уходят в таблицу редиректов |
| Права ролей          | `permissions.ts`                        | `role?.id === 'commander'` в экранах. Правило «кто подтверждает» остаётся в `domain/archive.ts`, модуль прав на него ссылается                                             |
| Слои карты (шаг A)   | `functions/mapLayers`                   | Сборку меток маршрута, мест, захоронений и хроники внутри экранов                                                                                                          |

**Реестр функций** (`src/functions/registry.ts`, шаг A) описывает каждую функцию: `id`, строки реестра `FEATURES.md`, раздел интерфейса, адреса, пункт меню, слой карты, карточку роли и **эндпоинты контракта**, то есть места подключения к бэкенду.

- Включение и выключение — только в корне приложения: адреса, меню, слои, карточка роли. Сборка — `VITE_FEATURES_OFF`, демо — пульт `/demo`. В экранах проверок флагов нет.
- Тест следит, что каждый эндпоинт принадлежит ровно одной функции.
- Командой `npm run connections` строится `docs/CONNECTIONS.md`: функция → эндпоинты → mock или live.
- Переключение на live по функциям (`VITE_LIVE_FEATURES`) через составной `ApiClient`: бэкенд готов не целиком.

## Правила импорта (проверяет `src/architecture.test.ts`)

1. Экраны и оболочка не импортируют `api/`, `platform/`, `@tanstack/react-query` и `app/services`. Исключение — корень композиции: `main.tsx`, `app/App.tsx`, `app/services.tsx`.
2. В `functions/` нет `.tsx`, `react-router`, экранов и `app/`. Сервисы подключает только `functions/core/useDeps.ts`. Сценарии (не `use*.ts`) не импортируют React.
3. Между функциями нет циклов, `functions/core` не зависит от функций.
4. `domain/`, `contract/`, `api/` не импортируют React, DOM-библиотеки и роутер.
5. Адреса экранов записаны только в `functions/core/paths.ts`.
6. Права ролей — только `can(role, действие)` из `functions/core/permissions.ts`: сравнивать роль с id (`=== 'commander'`) можно только там и в `domain/` (R3).

Импорты разбираются компилятором TypeScript (`ts.preProcessFile`): учитываются `import()`, `export … from` и `?worker&url`. Новой зависимости нет. Файлы, которые ещё не переведены, записаны в тесте списком исключений. Тест падает и на новое нарушение, и на исключение, которое уже не нужно. К концу шага A список пуст.

## Шаг A не меняет поведение и вид

- Все тесты зелёные на каждом коммите.
- Визуальный тест (`npm run visual`) сравнивает 22 экрана × 2 вьюпорта с эталоном, снятым до шага A, порог 0. Экраны без карты снимаются целиком, экраны с картой — видимая область: полностраничный снимок растягивает окно, и карта перестраивается.
- Память на устройстве читает данные так же, как раньше (без новой проверки схемой). Проверка схемой — шаг C, отдельным тестом.

## Последствия

- Разложить функции по новой раскладке (шаг B) — значит переставить компоненты, а не переписывать сценарии.
- Android: сценарии и `core` без React переносятся как есть, платформу подменяет `platform/capacitor`.
- Цена: больше файлов, у каждой функции `index.ts`. Экраны становятся тоньше, сценарии проверяются без рендера.
