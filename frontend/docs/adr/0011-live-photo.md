# ADR 0011. «Живое фото»: заранее сгенерированные ролики и WebAR через MindAR

- Статус: принято
- Контекст: снимок бойцов с QR-кодом должен «заговорить» при наведении камеры. Без установки приложения, на обычном телефоне, по HTTPS-ссылке. Видеокарту компьютера команды не нагружаем.

## Решение

- **Ролики готовятся заранее, в облаке.** Генерировать видео в момент сканирования медленно и дорого, и без сети не работает. Голоса — ElevenLabs v3 (многоголосый диалог), говорящее лицо офицера — Hedra, групповой кадр — Kling 3.0; всё через агрегатор ERA2.ai. Бесплатный запасной путь — Edge TTS и Hugging Face Spaces (LTX-Video, MoDA). Локально только склейка ffmpeg. Скрипты — `scripts/live-photo/`.
- **Распознавание снимка — MindAR (MIT)**: снимок сам является меткой, QR только открывает страницу. Ролик ложится текстурой three.js ровно на рамку снимка.
- **Библиотеки с jsDelivr, только на экране камеры.** Пакет `mind-ar` из npm тянет tfjs, mediapipe и нативный `canvas`, который плохо собирается на Windows и в CI. Готовая сборка с CDN загружается динамически и не утяжеляет остальное приложение. `three` подставляется картой импорта в `index.html` (той же версии).
- **За интерфейсом платформы** (`platform.ar`) — в Android (Capacitor) заменяется нативным AR без изменения экранов.
- **Этика по кейсу** — согласие до просмотра, постоянная пометка «Реконструкция с помощью ИИ», текст речи виден заранее, субтитры.

## Отклонено

- Генерация на телефоне или сервере в момент сканирования — медленно, дорого, зависит от сети.
- 8th Wall, Zappar — платные.
- Подгонка губ каждого бойца на групповом снимке — облачные модели работают с одним лицом; общий план Kling с «радио» выглядит естественнее, чем пять склеенных говорящих голов.
- Распознавание лиц (MediaPipe) вместо снимка — не даёт точного наложения ролика на рамку и грузит модели с зарубежного CDN.
