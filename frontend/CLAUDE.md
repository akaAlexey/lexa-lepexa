# CLAUDE.md — фронтенд «Тропа памяти»

Новая сессия: сначала прочитай [`docs/HANDOFF.md`](docs/HANDOFF.md) и реестр функций [`docs/FEATURES.md`](docs/FEATURES.md) — цель, рамки, этапы, что сделано и что дальше.

## Команды (из `frontend/`)

| Команда                                        | Что делает                                                                                       |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `npm run dev`                                  | dev-сервер Vite                                                                                  |
| `npm run verify`                               | **приёмка:** typecheck → lint → prettier --check → unit + компонентные → e2e (телефон и ноутбук) |
| `npm test` / `npm run e2e`                     | только Vitest / только Playwright                                                                |
| `npm run fixtures`                             | данные жюри `fixtures/jury/*` → `src/api/fixtures/jury.generated.json` (с проверкой схемой)      |
| `npm run contract`                             | zod-контракт → `../docs/openapi.json` (тест падает, если забыть)                                 |
| `npm run visual`                               | визуальный контроль рефакторинга: 22 экрана × 2 вьюпорта против `e2e-visual/baseline`            |
| `npm run tunnel`                               | временный HTTPS `https://*.lhr.life` для телефона (живёт, пока идёт процесс)                     |
| `DEPLOY_TARGET=user@host:/path npm run deploy` | сборка и rsync на VPS с `deploy/Caddyfile`                                                       |

Скриншоты e2e: `e2e/screenshots/<phone|laptop>/*.png`. Отчёт Playwright: `playwright-report/`.

## Правила

- **Отчитываемся поведением, тестами и скриншотами, а не кодом.** «Готово» — только после зелёного `npm run verify` и просмотра скриншотов в двух вьюпортах (субагент `fe-verifier`).
- В начале сессии: `git fetch` и сверка с `origin/main` — контракт бэкенда мог измениться.
- Ветка `frontend`. Маленький коммит на каждый осмысленный шаг (Conventional Commits, `feat(frontend): …`), регулярный `git push origin frontend`. Нельзя: force-push, коммиты в `main`, секреты в репо.
- Интерфейс на русском. Одна большая красная кнопка (`BigButton`) на экран; главный сценарий роли — не больше 3 нажатий.
- Доступность: зоны нажатия от 48 px (`--touch-min`), шрифт 18 px, контраст AA, статус не только цветом (иконка + подпись), у интерактивных элементов подпись для скринридера и `data-testid`, у каждого экрана и карточки свой URL.
- Цвета, шрифты, размеры — только из `src/theme/tokens.ts` (дизайн будут править с командой). Стиль карты — тоже из токенов (`color.map`).
- Подложка карты — только через `VITE_TILES` / `src/map/tiles.ts`. Карту и AR будут дорабатывать: не зашивать источник тайлов в экраны.
- Данные — только через функции (`src/functions`, сервисы — через `useDeps()`); новая сущность начинается с `src/contract/`, затем mock, затем `npm run contract`.
- Платформенное (геопозиция, уведомления, хранилище, камера и AR, «поделиться») — только через `src/platform`.
- Этика: демо-данные с `demo: true` и плашкой, у каждого факта `sources`, никаких очков «за погибших», платежи только в тестовом режиме, «Живое фото» — согласие родственников + «создано ИИ» + оговорка.
- Каждую новую зависимость обосновать (веб + будущий Android), мёртвый код не оставлять (`fe-simplifier`).
- Функции — в `src/functions/<функция>/` (сценарии без React + хуки + тесты), экраны только собирают раскладку (ADR 0008, тест архитектуры). Реестр функций — `docs/FEATURES.md`: статус меняется только вместе с зелёными тестами в том же коммите.
- Поправка арбитра = новое правило в этом файле.

## Тесты — спецификация

- Поведение P0 описано тестами и [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md). URL и `data-testid` оттуда — контракт: менять только вместе с тестами.
- Утверждённые тесты не ослабляем и не удаляем. Кажется неверным — спросить арбитра.
- `npm run verify` зелёный на каждом коммите в `frontend`.
- Скриншоты для документации: `npm run screenshots` (настоящая подложка, сжатие) → `docs/screenshots/`.

## Границы — не трогать

- Код, конфиги и CI бэкенда.
- Корневой `README.md` — только раздел «Фронтенд» со ссылкой.
- Общие с бэкендером файлы: `docs/API_CONTRACT.md`, `docs/openapi.json` (генерируется), `docs/BACKEND_REQUESTS.md`.
- `.claude/settings.json` в корне — общий; добавлять, не затирать чужое.

## Правила от арбитра

- Хостинг пока не подключён: весь каркас собирается и проверяется локально; для телефона — `npm run tunnel`.
- По AR, картам и дизайну будут правки с командой: держать их заменяемыми (токены, `tiles.ts`, `MapView` API).
- Бэкенд пишет другой человек: фронт не ждёт его, работает на mock-адаптере.
- Главная — «Мероприятия» (`/` → `/events`), выбор роли — `/roles` и «Другое → Роль» (спринт v3.2).
- Записаться можно только через окно с условиями: начало и конец, место сбора, что взять, возраст. Без подтверждённого возраста 18+ — только с согласием родителя. Кнопок «записаться одним нажатием» нет.
- «Демо» — пометкой у самих демо-данных (`DemoBadge`), не надписью в шапке.
- Дизайн — по `docs/design/new_design/` (ADR 0012, решение арбитра 2026-09-24), а не по «Полевому атласу». Правила доступности сильнее прототипа.

## Грабли (проверено на практике)

- Системный Node собран **без поддержки TypeScript** (`--experimental-strip-types` падает) → скрипты запускаем через `tsx`.
- В zsh переменная `path` связана с `PATH`: `for … read path` ломает все команды. Не называйте переменные `path`.
- `pkill -f <шаблон>` убивает собственную оболочку, если шаблон есть в команде. Останавливайте фоновые задачи по ID.
- `curl` без `-m` может зависнуть на старте сервера — всегда ставьте таймаут.
- MapLibre 6 ищет воркер рядом со своим чанком → в Vite нужны `optimizeDeps.exclude: ['maplibre-gl']`, `worker.format: 'es'` и `setWorkerUrl(... ?worker&url)` (уже сделано в `MapView`). Регресс ловит e2e-проверка ошибок консоли.
- `markers` в `MapView` — только стабильный массив (`useMemo`), иначе бесконечный цикл перерисовки.
- В jsdom нет WebGL: `MapView` в тестах подменён `src/test/MapViewStub.tsx`. У тестов в среде jsdom `import.meta.url` не `file:` — JSON читаем импортом, чистые тесты помечаем `// @vitest-environment node`.
- Маска `canvas` на скриншотах Playwright закрывает и метки поверх карты — не маскируем; e2e идут с `VITE_TILES=none`, картинка стабильна.
- Полностраничный скриншот рисует `position: fixed` меню посреди страницы — снимаем видимую область.
- Бесплатный localhost.run (`npm run tunnel`) каждые несколько минут выдаёт новый адрес — старый отвечает 503. Актуальный адрес — последняя строка `*.lhr.life` в выводе; QR генерировать прямо перед проверкой. Решение арбитра: пока так, до постоянного хостинга.
- Git в этой среде: глобальный прокси `10.0.0.1:3128` не пускает к GitHub → в локальном конфиге репо прокси отключён, креды — в `~/.config/lexa/git-credentials`.
- Chromium для Playwright ставится напрямую: `npx playwright install chromium`.
- Субагенты с `isolation: worktree` создают worktree **от `main`**, а не от `frontend`: первым делом `git switch -c fe/<модуль> && git reset --hard frontend`. Worktree лежат в `.claude/worktrees/` (исключены через `.git/info/exclude`).
- Параллельные агенты: у каждого свой `E2E_PORT` (иначе `reuseExistingServer` подхватит чужую сборку); 5 агентов разом упираются в лимит сессии — агентов возобновляют через SendMessage, контекст сохраняется.
- Субагенты из `.claude/agents/` подхватываются только при старте Claude Code; в той же сессии — `general-purpose` с текстом роли из файла.
- Под нагрузкой: компонентные тесты рендерят приложение целиком (`testTimeout` 15 с, `asyncUtilTimeout` 3 с), e2e — лимит 60 с.
- Тост живёт внизу над меню и резервирует место (`--toast-space`) — иначе закрывает кнопки под собой (ловили в e2e).
- Шапка на 360 px должна переноситься (`flex-wrap: wrap`), иначе появляется горизонтальная прокрутка и меню уезжает.
- В e2e с настоящей подложкой тест «без сети» падает на ошибках тайлов в консоли — поэтому verify идёт с `VITE_TILES=none`, а `npm run screenshots` его пропускает.
- Windows: `git clone` с `core.autocrlf=true` даёт CRLF, и `prettier --check` падает на всех файлах → в репо `git config core.autocrlf false` и `core.eol lf`, затем перечекаут. `webServer.command` в `playwright.config.ts` написан под POSIX (`VITE_TILES=… npm …`): на Windows собрать `npm run build:e2e`, поднять `vite preview --host 127.0.0.1 --port $E2E_PORT` отдельно — Playwright переиспользует сервер.
- Карта на ноутбуке — `position: fixed` справа от панели экрана: у предков `.screen` не должно быть `transform`/`filter`, иначе карта уедет в поток.
